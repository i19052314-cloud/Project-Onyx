### M1 — государства и карта

| Компонент | Файл | Что делает |
|---|---|---|
| Модель | `Sim/World.cs`, `Sim/Nation.cs`, `Sim/Region.cs`, `Sim/Vec2.cs` | Чистые данные: ни одного натива, ни одной ссылки на SHVDN |
| Геометрия | `Sim/Geometry.cs` | `PointInPolygon`, площадь, центроид, расстояние до границы |
| Конфиг | `Core/Config.cs` + `OnyxNations/Data/*.xml` | XmlSerializer → модель, валидация ссылок (владелец, претендент, столица, соседи) |
| Данные | `OnyxNations/Data/Nations.xml` (авторские), `OnyxNations/Data/Regions.xml` (сгенерированные) | 2 государства, 14 регионов |
| Отслеживание | `Presentation/RegionTracker.cs` | Позиция игрока → регион, событие только при реальной смене, интервал 250 мс |
| Интерфейс | `Presentation/Draw.cs`, `Presentation/Overlay.cs` | HUD-панель, планшет (`F8`) со сводкой по государствам и таблицей территорий, тосты |
| Генератор карты | `tools/build_regions.py` | k-means → centers → ячейки Вороного, проверка покрытия/смежности |

**Игровые правила, которые уже работают:**

- регион всегда определён (внутри карты — по полигону, вне — по ближайшему центру);
- владелец региона меняется вызовом `World.SetOwner()`; при оккупации контроль
  падает со 100 % до 35 %, при освобождении возвращается к 100 %;
- смена владельца сразу сохраняется и **переживает перезапуск** (проверено тестом
  round-trip);
- `original owner` хранится в геометрии/конфиге, поэтому флаг «оккупирован»
  (`Owner != OriginalOwner`) восстанавливается после рестарта;
- игральные часы идут ×2 к реальному времени (1 игровой день = 48 реальных минут).

## 2. Карта: как получена и почему ей можно верить

Геометрия не выдумана. Источник — **865 почтовых точек** из состава Onyx RP
(`ProjectOnyx/Data/Postals.xml`), у каждой мировые X/Y.

1. k-means++ (детерминированный, seed 1337) → 14 кластеров;
2. центры кластеров — семена;
3. полигон региона — **ячейка Вороного** семени, отсечённая по габаритам карты.
   Ячейки Вороного **покрывают плоскость без зазоров и наложений**, поэтому
   «в каком я регионе» всегда имеет ровно один ответ;
4. принадлежность государству, названия, население и ценность — авторские;
5. всё проверяется (`tools/build_regions.py`):
   - каждая из 865 точек попадает ровно в один регион — **OK**
   - `point-in-polygon` совпадает с «ближайший центр» для всех точек — **OK**
   - все полигоны не вырождены — **OK**
   - смежность симметрична — **OK**
   - сумма площадей ячеек = площади габарита (покрытие 1.000000) — **OK**

| Государство | Столица | Регионов | Население | Площадь |
|---|---|---|---|---|
| **Республика Сан-Андреас** (RSA) | Центр Лос-Сантоса | 10 | 2 320 000 | ~44.0 км² |
| **Федерация Западного Сан-Андреаса** (ФЗСА) | Пале́то-Бэй | 4 | 566 000 | ~40.0 км² |

Спорные территории: **`west_ls`** (Западный Лос-Сантос, владелец RSA, претендует ФЗСА)
и **`zancudo`** (Форт-Занкудо, владелец ФЗСА, претендует RSA).

Задуманный дисбаланс: у Республики люди и деньги, у Федерации — земля
(48 % карты) и военная база. Это топливо для войны, а не ошибка баланса.

## 5. Сборка и установка

1. Скопировать `ScriptHookVDotNet3.dll` из вашего **Legacy**-пакета SHVDN
   (3.6/3.7) в `lib/shvdn3/`.
2. Открыть `src/OnyxNations/OnyxNations.csproj` → сборка **Release** (нужен
   .NET Framework 4.8 targeting pack).
3. Скопировать:
   - `bin\Release\OnyxNations.dll` → `<GTA>\scripts\`
   - `OnyxNations\OnyxNations.ini` → `<GTA>\scripts\`
   - папку `OnyxNations\` (с `Data\`) → **корень игры**, рядом с `ProjectOnyx\`
4. Запустить Story Mode, включить Onyx (F9) — модуль грузится вместе с ним.

Удаление: стереть `scripts\OnyxNations.dll`, `scripts\OnyxNations.ini` и папку
`OnyxNations\`. Больше ничего этот модуль не создаёт и не трогает.

## 7. Первый запуск: если что-то не так

Порядок диагностики — сверху вниз. Логи: `<GTA>\OnyxNations\onyx-nations.log`
(наш) и `<GTA>\ScriptHookVDotNet.log` / `ScriptHookVDotNet-*.log` (рантайм).

| Симптом | Причина и что делать |
|---|---|
| Лога `onyx-nations.log` нет вообще | Скрипт не загружен. Смотреть `ScriptHookVDotNet.log`: там будет причина (не та версия .NET, DLL не в `scripts\`, исключение в конструкторе). Убедиться, что DLL лежит именно в `<GTA>\scripts\` |
| Лог есть, строка `config files are missing` | Папка `OnyxNations\` не там. В логе строка `data dir:` показывает, куда модуль смотрит — положите папку туда (или в `<GTA>\scripts\` — модуль находит оба варианта) |
| Лог есть, строки `config: ...` | Ошибка в XML (неизвестный владелец/столица/сосед). Модуль намеренно останавливается, а не работает на сломанных данных |
| Ошибки при сборке в Visual Studio | Пришлите текст ошибок — правлю быстро. Скорее всего, расхождение в API конкретной сборки SHVDN 3.7 |
| `F8` не открывает планшет | 1) посмотреть лог: дошли ли до `ready:`; 2) ключ может перехватывать другая модификация или сам SHVDN — смените `TabletKey` в INI (например на `F8`) |
| Вместо русского текста — квадраты/кракозябры | В INI `[General] Language=en` — интерфейс станет английским. Это шрифт GTA, а не ошибка кода |
| Панель не видна | В INI `[Debug] Overlay=true`; панель появляется только когда есть персонаж (не в меню/загрузке) |
| Вылет при старте игры | Уберите `scripts\OnyxNations.dll` и пришлите оба лога — разберусь |
