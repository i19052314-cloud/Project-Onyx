# tools/ — генераторы и проверки

Эти скрипты — часть сборки, а не одноразовые helpers. Они нужны, потому что
территориальная геометрия и контракт данных должны быть **проверяемыми** без
запуска GTA.

## build_regions.py

Пересобирает `OnyxNations/Data/Regions.xml` и превью карты, попутно проверяя
геометрию.

```bash
python3 tools/build_regions.py             # сгенерировать + проверить
python3 tools/build_regions.py --verify-only
python3 tools/build_regions.py --k 20      # другое число регионов (потребуется
                                           # дополнить таблицу REGION_DESIGN)
```

Источник координат — `ProjectOnyx/Data/Postals.xml` (865 почтовых точек с
мировыми X/Y) из состава Onyx RP: никаких «придуманных» координат.

Что проверяется перед записью:

| Инвариант | Зачем |
|---|---|
| каждая почтовая точка попадает ровно в один регион | нет «ничьих» зон и наложений |
| `point-in-polygon` == «ближайший центр» для всех точек | поиск региона детерминирован |
| все полигоны не вырождены | пустой регион сломал бы владение |
| смежность симметрична | границы государств (M2) строятся по смежности |
| сумма площадей == площади габарита | ячейки Вороного реально покрывают карту |

## test_world_data.py

Тесты контракта данных: 832 проверки по реальным `Nations.xml` /
`Regions.xml` / `UnitTypes.xml` / `Armies.xml` / `Borders.xml` / `Parties.xml` /
`People.xml`. Повторяет инварианты `OnyxNations.Sim.World.Validate()` и
сценарий сохранение → перезапуск → загрузка (регионы, казна, министры,
приказы юнитов, выборы, переходы). Первым делом проверяет, что все XML вообще
читаются: комментарий с `--` внутри ломает файл, и это уже случалось дважды.

```bash
python3 tools/test_world_data.py
```

## sim_reference.py

**Исполняемая эталонная модель** всей симуляции: экономика, бой, оккупация,
мозг ИИ. Пишется и настраивается первой — C# транскрибируется с неё. Так
утверждение «работает» проверяется, а не декларируется.

```bash
python3 tools/sim_reference.py --years 2
```

53 проверки: приказы реально двигают части, бои идут, территория меняет
владельца, ИИ без участия игрока сам объявляет войну и наступает, налог
поднимает казну и роняет настроение, уничтоженные части не возвращаются,
переходы лежат на реальной границе, популярный президент выигрывает, а
непопулярный теряет пост и уступает место партии с другой налоговой программой.

## check_parity.py

Сторож расхождения: C# нельзя скомпилировать в песочнице, поэтому он держится
рядом с работающим эталоном. Сверяет константы `SimTuning.cs`, данные
`UnitTypes.xml` / `Armies.xml` / `Nations.xml` / `Parties.xml` и арифметические
отпечатки формул. 239 проверок.

```bash
python3 tools/check_parity.py
```

## check_sources.py

Структурная проверка C# без компилятора (в песочнице разработки нет .NET SDK).
Ловит список файлов в csproj, баланс скобок, несуществующие `using`,
необъявленные типы и члены.

```bash
python3 tools/check_sources.py
```

**Это не компилятор.** Перед релизом проект обязательно собирается в Visual Studio.
